# Qiqi DataAgent 下一阶段讨论

核对基线：2026-09-21，远端 `master-branch` 提交 `050b8b5`，本轮开发分支 `codex/chart-mcp`。先保留现有 ReActAgent，在实际任务中补齐运行可靠性和数据分析能力。

## 接入前基线

前端已有美化后的工作台、主题、流式 Markdown、浏览器历史、并行对话、停止按钮、查询证据和本地配置页面。后端已有 AgentScope 2.0.3、DashScope / OpenAI 兼容模型、SQL 策略、部门范围、查询审计。当前源码中没有 Skills 注册或管理模块，不能把系统提示词与普通工具算作完整 Skills 支持。

本轮补齐图表 MCP：`execute_sql → queryId → generate_chart → mcp-echarts → metadata.chart → 图表卡片`。MCP 端点与超时由服务端配置，图表数据由服务端查询证据提供；三种图表共用同一条实现链路。保留原查询权限和美化后的页面。

## 接入前建议优先级

| 优先级 | 要补的能力 | 代码中的现状 / 实际影响 | 首个可验收目标 |
| --- | --- | --- | --- |
| P0 | 服务端会话持久化 | `DataAgentFactory` 使用 `InMemoryAgentStateStore`，页面历史在 localStorage；重启后“看得到记录”不等于 Agent 记得上下文 | 重启后继续同一会话，能引用已有定义、查询证据和附件；不同用户隔离 |
| P0 | 运行状态、取消与恢复 | 前端 AbortController 停止请求；后端没有专门的 runId、停止/恢复 API。同一会话跨标签页请求也缺少应用层互斥 | 区分生成中/成功/失败/取消，真正取消模型和工具；同会话冲突返回明确反馈；恢复时避免重复工具副作用 |
| P1 | 指标口径和业务术语 | 只有表结构与 SQL 工具；收入、退款、订单状态、时间范围仍主要靠模型解 释 | 增加受版本管理的指标定义、术语查找工具，先固定“已付款收入、订单数、客单价”的口径和边界 |
| P1 | 有用的 Skills | 当前未注册；不必先做复杂的上传管理后台 | 首先做“收入变化分析”和“部门对比”两个技能，按需加载流程、口径、推荐工具与输出要求；工具权限继续由服务端执行 |
| P1 | 图表与证据持久化 | 本轮是临时查询缓存 + 浏览器图表历史 | 保存查询结果快照、图表和用户归属；多设备回放；之后增加多序列、单位、Top N 和日期补齐规则 |
| P2 | 文件分析与结果导出 | 当前只有数据库查数和 Markdown 下载 | 先支持 CSV / Excel 预览、类型确认、受控分析与 CSV 导出，再评估大文件 RAG；数字计算继续交给 SQL / 确定性工具 |
| P2 | 工具发现、联网和故障观测 | 目前工具数量少；MCP 仅图表。事件映射主要是框架事件直接序列化 | 工具增多后引入按需发现；联网显式开关；记录 runId、toolCallId、延迟、错误、token 和成本；稳定应用自己的 SSE DTO |
| 上线前 | 正式身份与数据源治理 | `X-Qiqi-User` 是演示入口，H2 是内存数据，部门规则绑定销售示例模型 | 接真实认证和数据库只读账号；验证多部门/角色；对新业务表建立明确的行权限规则 |

## 架构选择

此时可以继续使用 ReActAgent。优先让“查数 → 解释 → 画图 → 追问”可靠，再决定是否使用 HarnessAgent 的持久化、上下文压缩、工作区和技能能力。切换前要逐项验证工具身份、事件格式和恢复行为；不要仅因名称更完整就同时更换所有运行边界。

只有当任务确实需要多个相对独立的研究或分析过程时，再讨论多 Agent。当前单一数据分析链路更需要统一指标口径、可靠证据和可恢复会话。

参考：[AgentScope 2.0 工具与 MCP](https://github.com/agentscope-ai/agentscope-java/blob/v2.0.3/docs/v2/en/docs/building-blocks/tool.md)、[AgentScope 2.0.3](https://github.com/agentscope-ai/agentscope-java/releases/tag/v2.0.3)、[mcp-echarts 0.7.1](https://github.com/hustcc/mcp-echarts/tree/0.7.1)。

## 本轮推进结果（2026-09-21）

按本轮确认，先推进 1、2、5、6、7，保留 ReActAgent：

| 项目 | 本轮交付 | 后续边界 |
| --- | --- | --- |
| 1 会话持久化 | 文件 AgentStateStore、服务端历史、浏览器缓存、历史版本冲突检测 | 多副本存储、自动迁移与保留期策略 |
| 2 运行控制 | runId、同会话互斥、服务端取消、断连取消、诊断恢复、沿用会话继续 | 不提供 Token 断点续传；继续基于已保存上下文，不自动重放工具 |
| 5 图表与证据 | 用户/会话查询快照、PNG 与图表元数据落盘、带身份校验读取与导出 | MinIO 保留期由存储服务管理；尚无自动清理 |
| 6 文件与导出 | CSV 上传、预览、全量确定性聚合、queryId 画图、CSV 和独立 Markdown 导出 | XLSX、多文件关联、大文件与自定义代码留后续 |
| 7 发现/联网/观测 | 原生工具组、每轮联网授权、Tavily 来源、取消/错误/阶段耗时/Token | 尚无实际成本计费、OpenTelemetry 或网页任意抓取 |

第 3 项可以用 YAML 保存，但“指标口径”本身包括业务定义、过滤条件、金额/日期字段、表关联与边界测试。
建议从收入、订单数、客单价三个指标开始，文件进 Git；如果没有口径校验和查询约束，仅增加 YAML 不会自动让 SQL 正确。

第 4 项当前仍无 Skills 注册。ReActAgent 2.0.3 本身支持 SkillRepository 与按需加载，无需为了 Skills 切换 Harness。

### HarnessAgent 工作量估计

在熟悉该代码的单个开发者、已有模型和环境的前提下，基于当前代码结构粗估：

- **1–2 人日**：在独立分支做最小试跑，替换装配、添加 Harness 依赖，跑通已有 SQL、图表工具与 SSE。
- **约 3–7 人日**：完成现有应用的可靠迁移，包括旧会话状态兼容、工作区权限隔离、取消恢复、工具发现/技能、事件适配和回归。
- **约 1–2 周或更多**：同时接多租户沙箱、分布式存储、长期记忆/上下文压缩与运维接入。实际范围需先做试跑核定。

SQL 校验、行权限、文件聚合和图表业务工具通常可保留；主要变化在 Agent 工厂和运行/状态边界。
Harness 默认的文件/工作区能力需要与数据权限一起核对，不能把换 Builder 当作上线完成。
业务指标、查询证据治理和文件导出仍是 Qiqi 的业务能力，不会因切换 Harness 自动具备。
